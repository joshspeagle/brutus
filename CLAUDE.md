# CLAUDE.md

brutus infers stellar properties, distances and extinctions from photometry and astrometry by evaluating Bayesian posteriors over a grid of stellar models (Speagle et al. 2025, arXiv:2503.02227). It fits individual stars, star clusters and 3D dust along a line of sight. The PyPI package is `astro-brutus`.

## Layout

- `src/brutus/`: the package. `core/` holds the stellar models (`EEPTracks`, `StarGrid`, `Isochrone`, `StellarPop`) and SED generation, `analysis/` the fitting (`BruteForce`, cluster and line-of-sight fitting, photometric offsets), `priors/` the IMF, Galactic and extinction priors, `dust/` the 3D dust maps, `data/` downloading (Pooch, Harvard Dataverse) and loading, `plotting/` the figures, and `utils/` math, photometry and sampling.
- `tests/`: the test suite, one directory per subpackage.
- `tutorials/`: Jupyter notebooks numbered 00 to 11. They need downloaded model data. The docs build copies them into `docs/source/tutorials/`.
- `docs/source/`: the documentation site (Sphinx with the Furo theme, Markdown pages through MyST). `_static/brutus.css` holds the brutus style; the theme colours are in `conf.py`. Read the Docs builds it at https://brutus.readthedocs.io, the address that `README.md` and `pyproject.toml` give; the docs workflow also deploys it to GitHub Pages from `master`.
- `bench/`: manual benchmark and verification tools for the `BruteForce` hot path, described in `bench/README.md`. Not packaged, not run in CI.
- `.github/scripts/fetch_test_data.py`: downloads the data the CI tests use.
- `CHANGELOG.md`: user-visible changes, in Keep a Changelog format.

## Commands

- Set up: `pip install -e ".[dev,docs]" pre-commit`, then `pre-commit install` once per clone.
- Test: `pytest`. Tests that need downloaded model data skip when it is absent; `python .github/scripts/fetch_test_data.py` downloads what CI uses.
- Coverage: `NUMBA_DISABLE_JIT=1 pytest --cov=brutus`. Without that variable, coverage cannot see inside `@jit` functions. Run plain tests with JIT on, so the compiled parallel code is what runs.
- Lint and format: `pre-commit run --all-files` (black, isort, flake8 and file hygiene).
- Docs: `cd docs && make html SPHINXOPTS="-W --keep-going"`. Warnings are errors, as in CI. The site builds into `docs/build/html/`.
- CI runs the tests on Ubuntu and macOS for Python 3.10 to 3.13 and builds the docs, for every push to and pull request against `master`. CI tests with `NUMBA_DISABLE_JIT=1` for coverage, plus one Ubuntu leg (Python 3.13) with JIT on. Before pushing a change to a jitted function, still run its tests locally with JIT on.

## Code

- Write the minimum code that is correct, clear and fast. Prefer removing to adding; deleting a concept beats adding a flag.
- Write no code when the change is not needed, or when the codebase, numpy, scipy or numba already does it.
- Validate public inputs early, with errors that name the argument and what was expected. Internal functions trust their callers. Leanness never removes input validation or numerical safety checks.
- Public functions never modify their input arrays.
- No no-ops (passing a default, guarding a case that cannot happen), dead code, or new linter-ignore rules.
- One purpose per function, one group of things per module. Add a helper only when it is reused or a function is too long.
- Names are readable words, except symbols that follow the paper's notation (`av`, `rv`, `feh`, `loga`, `eep`, `mini`).
- Keep the public API stable. A rename or removal needs a decision and a `CHANGELOG.md` line.

## Numerics

- Units: fluxes are maggies, `10**(-0.4 * mag)` in the survey's native system, with no zero-point offset. Model magnitudes are at 1 kpc, so `m = m_model + 5 * log10(d_kpc)` and `scale = 1 / d_kpc**2`. Parallaxes are in mas; multiply arcseconds by 1000. A(V) is in mag. brutus takes fluxes, not magnitudes (`brutus.utils.inv_magnitude` converts).
- Fitting evaluates every grid model. For each model it finds the best (scale, A(V), R(V)) by Gauss-Newton and forms their 3x3 Fisher matrix. Monte Carlo draws from that Gaussian, in log-distance `eta = ln(d)` with the Jacobian `exp(eta)` in the weights, integrate the priors. Sampling in scale instead biases distances by `1/d**3`.
- The prior draws are antithetic pairs `(z, -z)` (`sample_multivariate_normal(..., antithetic=True)`). The saved `mc_ess`, `1 / sum(w**2)`, therefore measures weight concentration, not a count of independent draws.
- In `_get_sed_mle`, `drvecs = (1 / A(V)) * df/dR(V)`. The Fisher terms that involve R(V), including the A(V)-R(V) cross-term, multiply by `av` to recover `df/dR(V)`. Without it the precision matrix is singular.
- The 3x3 precision matrix is inverted with diagonal preconditioning: scale to a correlation matrix, invert, scale back.
- Clamp the scale to `MIN_SCALE = 1e-20` (`analysis/individual.py`) before `log(scale)`. Use `LOG_ZERO = -1e300` for a zero probability, not `-np.inf`.
- A fit needs at least 4 bands (3 free parameters and 1 degree of freedom).
- Photometric offsets from `load_offsets()` multiply both flux and error in `BruteForce._setup()`. Their uncertainties (about 0.02 mag optical and 0.03 mag near-infrared, paper Table 5) are not added to the errors. The user converts each to flux, `flux * sys_mag * ln(10) / 2.5`, and adds it to the errors in quadrature.
- Priors: R(V) is Gaussian with mean 3.32 and standard deviation 0.18. The dust-map A(V) prior adds 0.2 mag of scatter in quadrature to the map spread (`logp_extinction(scatter=0.2)`). Where the map is masked, the prior is the normalized uniform over `avlim`, never an improper `ln p = 0`.
- To broadcast labels across Monte Carlo draws, use `np.tile(labels, Nmc)`, not `np.repeat`, which silently misaligns them.
- Hot loops are `@jit(nopython=True, cache=True)`; per-grid-point loops add `parallel=True` with `prange`, which is bitwise-identical because rows are independent. A change to a jitted function keeps a pure-Python path that works under `NUMBA_DISABLE_JIT=1`.
- Randomness comes from the random state the caller passes (`rstate`, or `rng` in `analysis/offsets.py`). Every function that draws random numbers takes one; tests always pass a seeded one.
- A change for speed keeps saved results bitwise-identical, or states the measured difference and why it is acceptable (`bench/fullfit.py` and `bench/disteq.py` check this).

## Fit quality

- Never use `chi2 / Nbands` as a quality metric. Use the p-value with `dof = obj_Nbands - 3`: `scipy.stats.chi2.sf(obj_chi2min, max(dof, 1))`. When a parallax is given, `obj_chi2min` includes its term and `obj_Nbands` counts it as one band.
- Thresholds: `p > 1e-3` is a good fit, `1e-6 < p <= 1e-3` marginal, `p <= 1e-6` poor (a model failure, a young star, a binary).
- For posterior predictive checks, compare the spread of predicted fluxes across draws with the measurement error, band by band. A ratio much above 1 means poorly constrained parameters.

## Behaviour to know

- `load_models` keeps the `afe` label only when it varies across the grid, as it does for `smf`. Requesting `afe` explicitly always keeps it.
- Bayestar queries apply the map's reliability mask by default: NaN outside each sightline's reliable distance range and in non-converged pixels, and a whole sightline when its bounds are NaN. `Bayestar(apply_reliability_mask=False)` returns raw values.
- `EEPTracks` caches are versioned (`*_cachev2.pkl`). Older unversioned `.pkl` caches are ignored.
- `quantile` uses the midpoint-CDF convention for weighted and unweighted samples, not `np.percentile`'s interpolation.
- `StarGrid.get_seds` raises `ValueError` when a multi-valued grid axis is omitted. A single-valued axis may be omitted.

## Tests

- Hermetic, except the model data that `brutus.data` downloads. A test that needs that data finds it with `tests/conftest.py:find_brutus_data_file` and skips when the data are absent. No other network access.
- Write a test only when it catches a plausible bug in this code that no other test catches.
- Test contracts, invariants, agreement with a reference implementation (each fast or jitted path against a direct computation), and regressions (each bug fix adds a test that fails without it). Do not test numpy's, scipy's or numba's behaviour.
- Mark a test `slow` when it loads a full model grid or takes more than 5 s on a CI runner.
- Statistical tests are seeded, with tolerances from the Monte Carlo error.
- Assert on numbers, never on wall-clock time.
- Name a test as a sentence that states the behaviour: `test_fully_masked_object_is_skipped`.
- When code changes, find the tests that call it directly, use it as a dependency, or run it end to end, and update them in the same pull request.

## Documentation

A docstring with LaTeX is a raw string (`r"""`).
- Private code needs no docstring; give it one only when its contract is not obvious from its name and signature. A comment explains only a non-obvious why, such as a numerical subtlety or the paper equation it implements.

- Lead with a summary, then the background a new reader needs.

- Active voice, simple tenses, and full sentences with articles.
