# CLAUDE.md

brutus infers stellar properties, distances and extinctions from photometry and astrometry by evaluating Bayesian posteriors over a grid of stellar models (Speagle et al. 2025, arXiv:2503.02227). It fits individual stars, star clusters and 3D dust along a line of sight. The PyPI package is `astro-brutus`.

This file is the canonical repository instruction set shared across Claude Code (`CLAUDE.md`), Antigravity (`.agents/rules/CLAUDE.md`), and OpenAI Codex (`AGENTS.md` symlink).

## Layout

- `src/brutus/`: the package. `core/` holds the stellar models (`EEPTracks`, `StarGrid`, `Isochrone`, `StellarPop`) and SED generation, `analysis/` the fitting (`BruteForce`, cluster and line-of-sight fitting, photometric offsets), `priors/` the IMF, Galactic and extinction priors, `dust/` the 3D dust maps, `data/` downloading (Pooch, Harvard Dataverse) and loading, `plotting/` the figures, and `utils/` math, photometry and sampling.
- `tests/`: the test suite, one directory per subpackage.
- `tutorials/`: Jupyter notebooks numbered 00 to 11. They need downloaded model data. The docs build copies them into `docs/source/tutorials/`.
- `docs/source/`: the documentation site (Sphinx with the Furo theme, Markdown pages through MyST). `_static/brutus.css` holds the brutus style; the theme colours are in `conf.py`. Read the Docs builds it at https://brutus.readthedocs.io, the address that `README.md` and `pyproject.toml` give; the docs workflow also deploys it to GitHub Pages from `main`.
- `bench/`: manual benchmark and verification tools for the `BruteForce` hot path, described in `bench/README.md`. Not packaged, not run in CI.
- `.github/scripts/fetch_test_data.py`: downloads the data the CI tests use.
- `CHANGELOG.md`: user-visible changes, in Keep a Changelog format.

CI tests with `NUMBA_DISABLE_JIT=1` for coverage, plus one Ubuntu leg (Python 3.13) with JIT on. Before pushing a change to a jitted function, still run its tests locally with JIT on.

## Code

- Write the minimum code that is correct, clear and fast. Prefer removing to adding; deleting a concept beats adding a flag.
- Write no code when the change is not needed, or when the codebase, numpy, scipy or numba already does it.
- Validate public inputs early, with errors that name the argument and what was expected. Internal functions trust their callers. Leanness never removes input validation or numerical safety checks.
- Public functions never modify their input arrays.
- No no-ops (passing a default, guarding a case that cannot happen), dead code, or new linter-ignore rules.
- One purpose per function, one group of things per module. Add a helper only when it is reused or a function is too long.
- Names are readable words, except symbols that follow the paper's notation (`av`, `rv`, `feh`, `loga`, `eep`, `mini`).
- Keep the public API stable. A rename or removal needs a decision and a `CHANGELOG.md` line.

## Numerics

- Units: fluxes are maggies, `10**(-0.4 * mag)` in the survey's native system, with no zero-point offset. Model magnitudes are defined at 1 kpc, so `m = m_model + 5 * log10(d_kpc)` and `scale = 1 / d_kpc**2`. Parallaxes are in mas (multiply arcseconds by 1000), and $A(V)$ is in mag. `brutus` takes linear fluxes rather than magnitudes (`brutus.utils.inv_magnitude` converts).
- Fitting evaluates every grid model. For each model it finds the best `(scale, A(V), R(V))` by Gauss-Newton iteration and forms their $3 \times 3$ Fisher matrix. Monte Carlo draws from that Gaussian in log-distance `eta = ln(d)` with the Jacobian `exp(eta)` in the weights integrate the priors, because sampling directly in `scale` biases distances by $1 / d^3$.
- The prior draws are antithetic pairs `(z, -z)` (`sample_multivariate_normal(..., antithetic=True)`). The saved `mc_ess` (`1 / sum(w**2)`) therefore measures weight concentration rather than a count of independent draws.
- In `_get_sed_mle`, `drvecs = (1 / A(V)) * df/dR(V)`. The Fisher terms that involve $R(V)$, including the $A(V)$-$R(V)$ cross-term, multiply by `av` to recover `df/dR(V)` because omitting `av` leaves the precision matrix singular when $A(V)$ varies.
- The $3 \times 3$ precision matrix is inverted with diagonal preconditioning by scaling to a correlation matrix, inverting, and scaling back.
- Clamp the scale to `MIN_SCALE = 1e-20` (`analysis/individual.py`) before `log(scale)`. Use `LOG_ZERO = -1e300` for a zero probability rather than `-np.inf`.
- A fit needs at least 4 valid bands because each model has 3 free continuous parameters (`scale`, $A(V)$, $R(V)$) and requires at least 1 degree of freedom.
- Photometric offsets from `load_offsets()` multiply both flux and error in `BruteForce._setup()`. Their calibration uncertainties (about 0.02 mag in the optical and 0.03 mag in the near-infrared, paper Table 5) are not added automatically to the errors; convert each to flux as `flux * sys_mag * ln(10) / 2.5` and add it to the observational errors in quadrature.
- Priors: $R(V)$ is Gaussian with mean 3.32 and standard deviation 0.18. The dust-map $A(V)$ prior adds 0.2 mag of scatter in quadrature to the map spread (`logp_extinction(scatter=0.2)`). Where the map is masked, the prior falls back to the normalized uniform density over `avlim` rather than an improper `ln p = 0`.
- To broadcast labels across Monte Carlo draws, use `np.tile(labels, Nmc)` rather than `np.repeat`, because `np.repeat` interleaves adjacent elements and silently misaligns grid labels with draw indices.
- Hot loops use `@jit(nopython=True, cache=True)`, and per-grid-point loops add `parallel=True` with `prange`, which remains bitwise-identical because rows are independent. A change to a jitted function keeps a pure-Python path that works under `NUMBA_DISABLE_JIT=1`.
- Randomness comes from the random state the caller passes (`rstate`, or `rng` in `analysis/offsets.py`). Every function that draws random numbers takes an explicit generator, and tests always pass a seeded one.
- A change for speed keeps saved results bitwise-identical, or states the measured difference and why it is acceptable (`bench/fullfit.py` and `bench/disteq.py` check this).

## Fit quality

- Evaluate fit quality using the survival-function p-value `scipy.stats.chi2.sf(obj_chi2min, max(dof, 1))` with `dof = obj_Nbands - 3` rather than raw reduced chi-squared `chi2 / Nbands`. When a parallax is given, `obj_chi2min` includes its term and `obj_Nbands` counts it as one band.
- Thresholds: `p > 1e-3` indicates a good fit, `1e-6 < p <= 1e-3` is marginal, and `p <= 1e-6` indicates a poor fit (such as an unresolved binary, a pre-main-sequence star, or an outlier band).
- For posterior predictive checks, compare the spread of predicted fluxes across draws with the measurement error band by band. A ratio much above 1 indicates poorly constrained parameters.

## Behaviour to know

- `load_models` returns every requested label, including constant axes (`afe` on a single-`afe` grid, or `smf` without binaries). `StarGrid` treats a constant axis as a single-value dimension, so querying it at another value raises `ValueError`.
- Bayestar queries apply the map's reliability mask by default, returning `NaN` outside each sightline's reliable distance range, in non-converged pixels, and across an entire sightline when its distance bounds are `NaN`. `Bayestar(apply_reliability_mask=False)` returns raw unmasked values.
- `EEPTracks` caches are versioned (`*_cachev3.pkl`), and caches from other versions are ignored.
- Numba checks a cached kernel against its own file only, so `brutus/_numba_cache.py` installs cache locators whose stamp also covers every file of the package. `brutus/__init__.py` imports it first, before any kernel is decorated.
- `quantile` uses the midpoint-CDF convention for weighted and unweighted samples rather than `np.percentile`'s linear interpolation.
- `StarGrid.get_seds` and `get_predictions` raise `ValueError` when a multi-valued grid axis is omitted, or when a label is non-finite or outside its axis range. A single-valued axis may be omitted.

## Tests

- Hermetic, except the model data that `brutus.data` downloads. A test that needs that data finds it with `tests/conftest.py:find_brutus_data_file` and skips when the data are absent, with no other network access.
- Write a test only when it catches a plausible bug in this code that no other test catches.
- Test contracts, invariants, agreement with a reference implementation (each fast or jitted path against a direct computation), and regressions (each bug fix adds a test that fails without it), without testing `numpy`, `scipy`, or `numba` internals.
- Mark a test `slow` when it loads a full model grid or takes more than 5 s on a CI runner.
- Statistical tests are seeded, with tolerances derived from the Monte Carlo standard error.
- Assert on numerical outputs rather than wall-clock time.
- Name a test as a full sentence that states the condition and expected outcome, such as `test_fully_masked_object_is_skipped`.
- When code changes, find the tests that call it directly, use it as a dependency, or run it end to end, and update them in the same pull request.

## Documentation

A docstring with LaTeX is a raw string (`r"""`).
- State what a module or class does and how its components fit together without promotional boilerplate (`"clean separation of concerns"`, `"key innovation"`, `"several advantages"`).
- Private code needs no docstring; give it one only when its contract is not obvious from its name and signature. A comment explains only a non-obvious why, such as a numerical subtlety or the paper equation it implements; never add `# Import X` banners or restate what the next line of code does.

Each fact has one home: `docs/source/` explains the background, the methods and how to use the code, `docs/source/api/` exposes each public symbol once (using `:no-members:` on submodule `automodule` blocks so cross-references resolve without duplicating member dumps), and `README.md` is a short introduction that links to the site. ## Writing

Prose across documentation, tutorials, docstrings, issues, and pull requests follows the Synergistic Prose Register (`<Dropbox>/.agents/memory/writing-and-voice.md`):

- **Concrete before formal:** Pair physical or statistical intuition with exact technical vocabulary before introducing formal equations. Cut restatement, filler, and lists of what did not change while keeping the background a new reader needs.
- **Explicit causal mechanisms (`because` clauses):** Explain why a constraint or behaviour holds using an explicit `because` clause or a second complete sentence (`"A star needs at least 4 valid bands because each model fits 3 free parameters"`), rather than joining clauses with a setup-and-reveal colon. Use colons only before lists, displayed equations, and quotations.
- **Direct positive statements:** State what the code does directly. Reserve `"X, not Y"` contrasts (at most one per page) for genuine domain misconceptions, such as fitting linear flux densities in maggies rather than magnitudes, or judging fits by the $\chi^2$ survival-function p-value rather than $\chi^2 / N_{\rm bands}$.
- **No anti-tics:** No em-dashes (`—`), meta-signposting openers (`"This page describes..."`, `"This section covers..."`), announced counts (`"three parameters"` instead of naming them), pseudo-clefts, colloquialisms (`"knob"`, `"trap"`), or mannered metaphors.
- **Consistent terminology and structure:** Use one term for one concept everywhere and define domain terms and abbreviations in parentheses on first use. Put a condition before the instruction it controls. Use numbered lists for sequential steps, bulleted lists with **bold content-naming lead-ins** for multifaceted items, and tables for comparisons.
